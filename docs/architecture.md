# ארכיטקטורה מומלצת (ממתינה לאישור לפני פתיחת שירותי ענן)

**אתר:** GitHub Pages (סטטי, דומיין `uronytools.com` כשיידרש). אין שרת. הכול בדפדפן.

## חלוקת נתונים
| מה | איפה | למה |
|---|---|---|
| מבחנים, שאלות אישיות, תמונות של מורה, העדפות | **Google Drive של המורה – `appDataFolder`** (תיקיית אפליקציה מוסתרת) | פרטיות מלאה: גם המנהל לא רואה. בלי עלות אחסון למערכת. |
| מאגר מרכזי (שאלות, סיווגים, סיפורי מקרה, מחוונים) | **Firestore (Spark)** | קריאה לכל מורה מחובר; כתיבה רק למנהל. |
| איורי המאגר המרכזי | מסמכי Firestore נפרדים (bytes ≤ ~900KB), במטמון IndexedDB אצל המורה | Firebase Storage מחייב Blaze. |
| הצעות שאלות | Firestore, אוסף `suggestions` | המורה כותב ורואה רק את שלו; המנהל קורא הכול. |
| הרשאת מנהל | Firestore, מסמך `admins/{uid}` (כתיבה אסורה לכל לקוח; נוצר ידנית בקונסולה) | לא ניתן לשינוי ע"י מורה. |
| גיבוי | מורה: "הורד גיבוי" (קובץ ZIP/JSON מהנתונים ב-Drive). מנהל: ייצוא המאגר המרכזי לקובץ | בלי תלות בשירות. |

## זהות והרשאות
- התחברות Google דרך Firebase Auth (זהות = `uid` קבוע, לא דוא"ל) + הרשאת Drive `drive.appdata` בלבד (scope **לא רגיש** לפי תיעוד Google; לא קורא קבצים אחרים של המורה).
- כללי Firestore: `bank/*` – קריאה למחוברים בלבד, כתיבה רק אם `exists(/admins/$(uid))`. `suggestions/{id}` – יצירה ע"י הבעלים בלבד (`authorUid == uid`), קריאה לבעלים ולמנהל, עדכון סטטוס רק למנהל.
- אישור הצעה: המנהל מעתיק את השאלה (כולל תמונות) מההצעה לאוסף `bank` כרשומה עצמאית. אין למנהל גישה ל-Drive של המורה: המורה *שולח* עותק.

## מבנה ב-Drive appDataFolder (קובץ לכל ישות, לא קובץ ענק)
`index.json` (רשימת מבחנים/שאלות + גרסאות) · `exam-<id>.json` · `pq-<id>.json` · `img-<id>.png|jpg`. מבחן מכיל עותקים עצמאיים של השאלות (כבר כך היום). אין כתיבה כפולה: בדיקת `modifiedTime`/`version` לפני דריסה בין מחשבים.

## מאגר מרכזי – מבנה חסכוני במכסות (50,000 קריאות ליום)
שאלות נארזות במסמכים של ~50 שאלות (טקסט בלבד, מתחת ל-1MiB); איורים נטענים בעצלתיים ונשמרים במטמון. טעינת מאגר שלם = עשרות קריאות, לא אלפים.

## סיכונים וצעדים נדרשים
- **אימות Google:** `drive.appdata` לא רגיש → צפוי אימות מותג בסיסי בלבד (שם אפליקציה, דף בית, מדיניות פרטיות, דומיין מאומת `uronytools.com`). יש לפרסם את ה-consent screen ל-"In production" (במצב Testing יש מגבלת משתמשים ותוקף חידוש קצר). עד האימות עשוי להופיע מסך "אפליקציה לא מאומתת".
- **דומיין:** github.io אינו ניתן לאימות כדומיין אצל Google (Public Suffix List), ולכן האתר חייב לשבת על דומיין בבעלותנו (`uronytools.com` או תת-דומיין עם CNAME ל-GitHub Pages, HTTPS חינם). אימות מותג דורש: דף בית (לא רק מסך התחברות), קישור למדיניות פרטיות באותו דומיין, ואימות הדומיין ב-Search Console. עד האישור יופיע מסך "אפליקציה לא מאומתת". סקירת scope כבדה לא נדרשת. חשבון Google קיים אחד מספיק; חשבונות Workspace של בתי ספר עלולים להיחסם ע"י מנהל המערכת שלהם.
- **תוקף:** access token של Google חי כשעה; בדפדפן בלבד אין refresh token, ולכן חידוש נעשה בשקט (GIS) בפעולה הבאה, ולעיתים יופיע חלון אישור קצר. כניסה אחרי חודשים: נדרשת כניסה מחדש בלחיצה אחת; הנתונים נשארים.
- **נתוני appData קשורים ל-OAuth client ID של הפרויקט:** אסור למחוק/להחליף אותו. מורה יכול למחוק את נתוני האפליקציה מהגדרות Google (זה גם הגיבוי להורדה).
- **Firestore Spark:** חריגה ממכסה יומית עוצרת פעולות עד היום הבא, בלי חיוב. לעולם לא לעבור ל-Blaze.

## מה כבר ממומש (מקומי) לפי החוזה
`src/store.js` – ממשק אחד (מאגר, מבחנים, מאגר אישי, הצעות, מדיה). כיום IndexedDB. הצעות מקומיות: סטטוס `pending`. מעבר לענן = `DriveStore` (אישי) + `FirestoreStore` (מרכזי/הצעות/מנהל) מאחורי אותו ממשק.

## מימוש בפועל (06.11.2026)
**Firestore (JSON בשדה טקסט, כי Firestore אוסר מערכים מקוננים כמו טבלאות):** `bank/meta` (חבילות, מילונים, רשימת איורים, rev) · `bank/q-NNN` (עד 60 שאלות / ~600KB) · `bank/c-NNN` (סיפורי מקרה) · `bankMedia/<hash>-<part>` (איור בחלקים של 700KB, נטען לפי צורך ונשמר במטמון מקומי) · `suggestions/sg-<uid>` + `suggestionMedia/*` (תמונות ההצעה נשלחות עם ההצעה כי למנהל אין גישה ל-Drive של מורה) · `audit/*` (יומן פעולות מנהל: יצירה בלבד) · `admins/<uid>` (נוצר ידנית בקונסולה).
**הרשאות:** `firestore.rules` – קריאה למחוברי Google; כתיבה למאגר/מדיה/עדכון הצעות/יומן רק למנהל; הצעה נוצרת רק על שם הכותב, בסטטוס pending, עם שדות מוגדרים בלבד, ואי אפשר לדרוס אותה אחר כך. בדיקות: `scripts/test-rules.mjs` (64 תרחישים באמולטור) ו-`scripts/test-cloud-emulator.mjs` (הקוד האמיתי מול האמולטור: מורה א׳/ב׳/מנהל/מזייף דגל).
**תור שמירה (`src/outbox.js`):** כל כתיבה ל-Drive נרשמת קודם במחשב ונמחקת רק אחרי הצלחה; בתקלה – שגיאה גלויה, הנתונים נשמרים ומסונכרנים אחר כך; גרסה ישנה לא דורסת חדשה בענן. חשבון בלי הרשאת Drive: אישי נשאר מקומי עם אזהרה.
**הרצת בדיקות עם אמולטור (דורש Java 21):** `npm run test:full` (או CI: `.github/workflows/ci.yml`).

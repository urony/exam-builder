# הפעלת הענן – מדריך קצר (דורש אישור המשתמש לפני כל שלב)

כל השלבים כאן נעשים בקונסולת Firebase של הפרויקט `urony-exam-builder`. אף אחד מהם לא בוצע עדיין.

## 1. Authorized domains (בטוח, לא פותח נתונים)
Firebase Console → Authentication → Settings → Authorized domains → Add domain. להוסיף:
- `localhost` (לבדיקות מקומיות)
- `exams.uronytools.com` (האתר, כשיפורסם)

בלי זה, התחברות Google מהאתר המפורסם תיכשל עם `auth/unauthorized-domain`.

## 2. פרסום כללי Firestore
Firebase Console → Firestore Database → Rules. מוחקים את התוכן (`allow read, write: if false`), מדביקים את כל תוכן הקובץ `firestore.rules` מהמאגר ולוחצים Publish.
- הכללים נבדקו באמולטור (66 בדיקות כללים + 34 בדיקות של הקוד האמיתי).
- אחרי הפרסום: מורה מחובר קורא את המאגר המרכזי ושולח הצעות; רק מנהל כותב.
- אם משהו נכשל: לא פותחים את הכללים. בודקים את הודעת השגיאה ב"פרטים טכניים" באתר.

## 3. יצירת הרשאת מנהל (`admins/<uid>`)
1. מתחברים לאתר עם Google (פעם אחת, כדי שהמשתמש ייווצר).
2. Firebase Console → Authentication → Users → מעתיקים את **User UID** של החשבון שלכם.
3. Firestore Database → Data → Start collection: מזהה אוסף `admins`; מזהה מסמך = ה-UID שהועתק; שדה אחד כלשהו, למשל `role` (string) = `admin` → Save.
4. טוענים מחדש את האתר: תופיע לשונית "ניהול" ובאנר "מחובר כמנהל".

חשוב: רק ביצוע ידני בקונסולה יוצר מנהל. אף משתמש (גם מנהל) לא יכול ליצור או לשנות מסמכי `admins` דרך האתר (הכללים אוסרים). להסרת מנהל: מוחקים את המסמך בקונסולה.

## 4. בדיקה ראשונה בענן (לפני פרסום האתר)
בהרצה מקומית (`npm run dev`) עם חשבון המנהל: ייבוא חבילה קטנה ("ייבא כמוסתר"), פרסום שאלה, התחברות מחשבון מורה אחר, שליחת הצעה, אישור בצד המנהל. כך בודקים מול Firestore אמיתי בלי לפרסם את האתר.

## 5. פרסום האתר (רק אחרי אישור נפרד)
GitHub → Actions → "Deploy to GitHub Pages" → Run workflow. הדומיין `exams.uronytools.com` כבר מוגדר ב-DNS.

## מה לא לעשות
- לא לפתוח כללים (`if true`) כדי לעקוף שגיאה.
- לא להעלות חבילות ZIP, בנק שאלות או מבחנים למאגר GitHub (המאגר ציבורי).
